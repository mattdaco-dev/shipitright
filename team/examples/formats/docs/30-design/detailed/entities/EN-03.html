Modèle physique

À quoi sert
Donner le schéma physique de l'entité, assez précis pour écrire la migration.
Contenu
Le DDL SQL dans le dialecte du store, chaque contrainte commentée par la règle qu'elle tient, puis les règles que la base ne peut pas tenir et l'endroit où elles vivent.
Pourquoi ce formalisme
Le DDL est ce que contient la migration : le dev le reprend sans traduction.
Lire
Un index porte en commentaire la requête qu'il sert ; une colonne d'une release suivante porte sa release, à titre indicatif. Les conventions communes sont dans la persistance.
CREATE TABLE salles (
  id             INTEGER PRIMARY KEY,
  nom            TEXT NOT NULL CHECK (length(trim(nom)) BETWEEN 1 AND 60),     -- BR-10
  capacite       INTEGER NOT NULL CHECK (capacite BETWEEN 1 AND 200),           -- BR-09
  statut         TEXT NOT NULL DEFAULT 'active' CHECK (statut IN ('active','desactivee')),  -- BR-08
  desactivee_le  TEXT NULL,                                                     -- ISO 8601 UTC
  cree_le        TEXT NOT NULL,                                                 -- ISO 8601 UTC
  CHECK ((statut = 'desactivee') = (desactivee_le IS NOT NULL))
);
CREATE TABLE salle_equipements (                                                -- BR-09, plusieurs à plusieurs
  salle_id       INTEGER NOT NULL REFERENCES salles(id),
  equipement_id  INTEGER NOT NULL REFERENCES equipements(id),                   -- EN-04
  PRIMARY KEY (salle_id, equipement_id)          -- sert le filtre d'équipements de EP-07 et PROC-04
);
-- liste des salles (EP-04)
CREATE INDEX salles_statut_nom ON salles(statut, nom);
-- BR-10 : deux salles actives ne portent pas le même nom (Q-003) ; le domaine contrôle avant
-- (NOM_SALLE_PRIS), l'index est le filet
CREATE UNIQUE INDEX salles_nom_actif ON salles(nom COLLATE NOCASE) WHERE statut = 'active';
