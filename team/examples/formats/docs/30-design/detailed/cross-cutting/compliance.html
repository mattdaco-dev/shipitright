Contrat de conformité : les invariants du code

Ce que le code respecte, quel que soit le ticket. Le dev s'auto-revoit dessus avant de rendre, le Relecteur vérifie chaque invariant et le cite par son identifiant. Un invariant non respecté est bloquant, sauf écart accepté avec son ADR.

Version v0.5 Date 08.10.2026 Auteur Architecte (exemple de format) Statut en revue

Invariants du socle de stack

À quoi sert
Dire quels invariants de la stack s'appliquent au projet.
Contenu
Le socle déclaré, les invariants repris par référence, ceux qui ne s'appliquent pas avec leur raison, et, tant que le socle est « à compléter », les invariants provisoires qu'il aura.
Pourquoi ce formalisme
Les invariants d'un socle servent à plusieurs projets et vivent dans son compliance.md : les reprendre par référence évite deux versions d'un même invariant. Un invariant provisoire porte déjà l'identifiant qu'il aura dans le socle : ni le code ni les revues n'auront à changer.
Lire
Un invariant repris par référence n'a pas de ligne ici : une page qui le cite lie cette section (compliance.html#stack-foundation), le générateur le fait seul.

Non applicables

Invariants provisoires du backend

Le socle n'a aucun invariant backend. Ceux-ci s'appliquent à tous les tickets backend jusqu'au socle complété, où ils seront reportés puis retirés d'ici ; l'humain les valide avec le socle à G2 (point ouvert de l'organisation du code). Ils traduisent ADR-0001 à ADR-0004 et le découpage par cas d'usage du socle de référence.

IdInvariant provisoire (backend Node, Fastify, better-sqlite3)Vérification
INV-01Packaging par cas d'usage, pas par couche : domain/<agregat>/command/<cas> pour une écriture, domain/<agregat>/query/<cas> pour une lecture ; la route, le handler et la commande du cas vivent ensemble, dans le module que déclare l'opération (modules). Seules les implémentations SQLite vivent dans infra/.aucun dossier services, models, dao transverse
INV-02Le domaine n'importe ni Fastify, ni better-sqlite3, ni node:http.imports sous domain/
INV-03Un dépôt est une interface du domaine (port) ; son implémentation SQLite est branchée à la racine de composition, jamais instanciée dans un handler.le handler reçoit le port en paramètre
INV-04Handler fin, règles dans le domaine : la route décode et encode, le handler orchestre, les règles BR-xx vivent dans les entités, objets de valeur ou fonctions pures du domaine.pas de condition métier dans une route
INV-05Les erreurs métier sont des valeurs (type résultat à union discriminée), pas des exceptions. Une exception reste un imprévu technique.aucun throw sous domain/
INV-06SQL écrit à la main, en requêtes préparées seulement ; aucune concaténation de valeur dans une requête.recherche de gabarits de chaîne dans infra/sqlite
INV-07Le schéma de base n'évolue que par une migration SQL numérotée ; une migration appliquée n'est jamais modifiée.historique de migrations/
INV-08Chaque route déclare son schéma de requête et de réponse (JSON Schema aligné sur openapi.yaml) et le rôle exigé ; une route sans rôle déclaré est refusée au démarrage.déclaration des routes, test de démarrage
INV-09Aucune réponse d'erreur ne contient de détail technique (pile, SQL, nom de table) : application/problem+json avec le code du contrat d'API (Probleme).test d'une erreur 500 et d'un refus du déclencheur

Invariants du projet

À quoi sert
Poser ce que la conception détaillée impose au code de ce projet, de façon vérifiable par le Relecteur.
Contenu
INV-60 à INV-69, chacun avec en lien les objets qu'il protège.
Pourquoi ce formalisme
Une page d'objet dit comment le construire ; un invariant dit ce qui ne doit jamais arriver, d'un objet à l'autre, et se vérifie en lisant le code.
IdInvariantVérification
INV-60Toute écriture qui pose, déplace ou réactive une réservation passe par la transaction immédiate (BEGIN IMMEDIATE) et par le contrôle de conflit du domaine (PROC-02), y compris pour une série (ADR-0002). Le handler de l'endpoint ouvre et ferme la transaction par le port UnitOfWork ; un traitement n'en ouvre, n'en valide ni n'en annule jamais (transactions).aucun INSERT ou UPDATE de reservations hors de cette transaction ; aucun appel à UnitOfWork sous un traitement
INV-61Les déclencheurs de non-chevauchement de EN-05 existent et leur condition est identique à celle de la requête de conflit du domaine (bornes strictes, réservations actives, même salle, même jour). Un test les vérifie toutes les deux sur les mêmes cas, dont 10:00-10:00.migration et test du dépôt
INV-62Le domaine lit l'heure courante par une horloge injectée, au fuseau Europe/Luxembourg ; jamais Date.now() ni new Date() sans argument sous domain/.recherche sous domain/
INV-63Le titulaire d'une réservation ou d'une série est toujours l'employé de la session ; aucun schéma de requête n'accepte d'identifiant d'employé (additionalProperties: false).schémas des routes et du YAML
INV-64Le front traduit les erreurs par leur code du contrat d'API, jamais par title ni detail ; chaque valeur de CodeErreur a sa traduction.service de traduction des erreurs, test qui parcourt l'enum
INV-65Les textes MSG-xx et MSG-Uxx vivent dans un catalogue unique du front, au mot près de la conception fonctionnelle et de la spec UX/UI ; aucune chaîne de message en dur dans un template.recherche des libellés dans les templates
INV-66Le front n'a aucune copie du calcul des occurrences (CALC-01, PROC-01) ni de la détection de conflit : il appelle EP-09. Seuls les sélecteurs filtrent les créneaux (BR-02, BR-03) pour guider la saisie ; le serveur reste juge.recherche d'un calcul de dates de série côté front
INV-67Aucune réponse ne renvoie l'email ni l'identifiant d'un autre employé que celui de la session : le titulaire d'une réservation d'autrui n'est exposé que par son nom (EP-06), et estAMoi est calculé côté serveur.schémas de réponse du YAML et des routes, test d'EP-06 avec deux comptes
INV-68Toute annulation de réservation (EP-12, EP-13, PROC-03) passe par une seule transition du domaine, PROC-06, qui vérifie BR-11, BR-03 et BR-07 et renseigne motif_annulation, annulee_le et annulee_par ; aucun UPDATE ... statut = 'annulee' hors du dépôt appelé par cette transition.recherche des écritures de statut dans infra/sqlite
