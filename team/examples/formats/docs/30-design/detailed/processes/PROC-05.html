PROC-05 : Calculer les taux d'occupation

Les indicateurs d'occupation du parc, calculés à la demande par agrégation SQL : à cette volumétrie, aucune table de cumul. Conception provisoire (EP-21) : les indicateurs ne sont pas encore définis par le métier, le point est ouvert sur l'opération.

Algorithme proposé

À quoi sert
Donner l'algorithme envisagé tant que l'opération qui appelle le traitement est provisoire.
Contenu
Les étapes envisagées, une par contrôle ou par action. Ce qui reste à trancher est dans les points ouverts de l'opération.
Pourquoi ce formalisme
Une liste numérotée, comme l'algorithme d'un traitement figé. Niveau réduit : le reste de la page s'écrit au sprint planning qui fige l'opération.
  1. Période du à au, 3 mois au plus, sinon PERIODE_INVALIDE.
  2. Heures ouvrées : nombre de jours ouvrés de la période × 11 heures (08:00 à 19:00, BR-02), calculé dans le domaine.
  3. Une requête, GROUP BY salle_id, sur l'index reservations(jour, statut), jointure sur salles pour le nom, désactivées comprises : heures réservées = SUM(fin_min - debut_min) / 60 des réservations active de la période, passées comprises ; annulations = COUNT des annulee.
  4. Taux = heures réservées / heures ouvrées, entre 0 et 1.
