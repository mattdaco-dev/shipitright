EN-06 : Série

La règle de récurrence d'un ensemble de réservations créées ensemble. Les occurrences sont des lignes de EN-05 qui pointent vers leur série : une occurrence s'annule seule (RG-06) et le contrôle de chevauchement ne connaît que des réservations.

Store SQLite table series Release MVP Version v0.3 Date 08.10.2026 Auteur Architecte (exemple de format) Statut en revue

Modèle physique

À quoi sert
Donner le schéma physique de l'entité, assez précis pour écrire la migration.
Contenu
Le DDL SQL dans le dialecte du store, chaque contrainte commentée par la règle qu'elle tient, puis les règles que la base ne peut pas tenir et l'endroit où elles vivent.
Pourquoi ce formalisme
Le DDL est ce que contient la migration : le dev le reprend sans traduction.
Lire
Un index porte en commentaire la requête qu'il sert ; une colonne d'une release suivante porte sa release, à titre indicatif. Les conventions communes sont dans la persistance.
CREATE TABLE series (
  id            INTEGER PRIMARY KEY,
  titulaire_id  INTEGER NOT NULL REFERENCES employes(id),                 -- EN-01
  salle_id      INTEGER NOT NULL REFERENCES salles(id),                   -- EN-03
  frequence     TEXT NOT NULL CHECK (frequence IN ('quotidienne','hebdomadaire')),  -- RG-04 ; 'mensuelle'
                                    -- en release R3 : SQLite ne modifie pas un CHECK, la migration reconstruit la table
                                    -- (nouvelle table, copie, suppression, renommage, dans une transaction)
  premier_jour  TEXT NOT NULL CHECK (premier_jour = date(premier_jour)),  -- RG-04
  jusqu_au      TEXT NOT NULL CHECK (jusqu_au >= premier_jour),           -- RG-04 ; la borne de 3 mois reste
                                                                          -- dans TR-01 (règles hors de la base)
  debut_min     INTEGER NOT NULL CHECK (debut_min % 15 = 0 AND debut_min >= 480),         -- RG-02
  fin_min       INTEGER NOT NULL CHECK (fin_min % 15 = 0 AND fin_min <= 1140
                                        AND fin_min > debut_min AND fin_min - debut_min <= 240),  -- RG-02
  cree_le       TEXT NOT NULL                                             -- ISO 8601 UTC
);
-- aucun index au-delà de la clé primaire : une série se lit par ses occurrences, reservations(serie_id)
-- dans EN-05 ; une occurrence est une ligne de EN-05 et s'annule seule (RG-06)

Règles hors de la base

  • Borne de 3 mois de RG-04 : dans TR-01 seulement. SQLite calcule date('2026-11-30', '+3 months') = 02.03, au lieu du 28.02 que retient TR-01 : une seule définition, dans le domaine, évite deux calculs qui divergent en fin de mois.
  • RG-05 (occurrences prises présentées avant validation, seules les libres créées) : calcul de TR-01 à l'aperçu (EP-09) et à la confirmation (EP-10).

Machine à états

À quoi sert
Montrer le cycle de vie de l'entité et ce qui la fait changer d'état.
Contenu
Une ligne par transition (de, vers, événement, garde, action), puis le diagramme d'états tiré de ce tableau. Sans cycle de vie, une phrase le dit.
Pourquoi ce formalisme
La notation UML événement [garde] / action, en deux vues d'une seule source : le tableau porte les liens et se relit ligne à ligne, le diagramme montre le cycle d'un coup d'œil.

Sans cycle de vie stocké. Une série est « en cours » tant qu'une de ses occurrences est active et future, « terminée » sinon. EP-13 annule ses occurrences, pas la série.
