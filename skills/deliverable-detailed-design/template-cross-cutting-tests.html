Technical test strategy: what the devs test

The unit and integration tests the devs write with their code. The e2e tests of the Gherkin criteria belong to QA. Each test of a rule cites its BR-xx (INV-56).

Open points

Purpose
List what remains to settle on the tests.
Content
One point per row, sorted by decreasing impact: the subject, the hypothesis the code follows meanwhile, the question Q-xxx if it is asked to the PO.
Why this formalism
A table, because each point has the same attributes and compares with the others.
Reading
  • high the answer can change the data model, a frozen operation of the API contract or what structures the whole code
  • medium the answer can change a provisional operation, a process, a schema not frozen or a screen
  • low the answer only changes a label, a message, a value or an edge case

Written here only once; the generator takes it over in the open points view.
