Signature and transaction

Purpose
Give the contract of the process in the code.
Content
Its signature in the language of the foundation (typed inputs, result, rejections as values of ErrorCode), then the transaction it runs in: always the one of its caller (transaction rule).
Why this formalism
A typed signature is the shortest and least ambiguous form; the dev copies it into the domain.
// module domain/aggregate
processName(
  cmd: { input: type },                  // where each input comes from
  deps: { repository: Repository; clock: Clock },
): Result<Output, 'ERROR_CODE'>
Transaction
the one of the caller, endpoints as links; a process without a caller (task, message) opens its own and says so
