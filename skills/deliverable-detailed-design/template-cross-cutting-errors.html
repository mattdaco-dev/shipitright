Error handling: codes, statuses, screens

Each error of the API carries a stable business code that the front translates into a message. The catalogue below is drawn from the API contract: for each code it gives the HTTP status, the case, what the user sees and the endpoints that return it.

Version v0.1 Date DD.MM.YYYY Author Architect Status draft

Principles

Purpose
Say how an error travels from the API to the screen.
Content
The format of the errors, the choice of the HTTP status, the translation by the front, the handling of an unknown code.
Why this formalism
A short list, each principle with the invariant that makes it checkable; the detail code by code is in the catalogue.
  • Format application/problem+json (RFC 9457), schema Problem. The code field takes a value of ErrorCode.
  • Request outside the schema in 400, missing session in 401, insufficient role in 403, unknown resource in 404, state conflict in 409, input rule in 422.
  • The front translates the code, never title nor detail, from a single catalogue of labels.
  • A code the front does not know (value added by a later release) is displayed as the technical error of the screen, without crashing (INV-59). Announced codes carry their release in the catalogue.
  • A code that puts an object in question (Entity column) is returned only by an endpoint or a process that declares that entity; the generator checks it. The translation screen by screen is in the screens view.
  • No response carries a technical detail (stack, query, table name). An unexpected error rolls back the transaction and answers INTERNAL_ERROR.
  • rules specific to the project, or remove this line

Code catalogue

Purpose
Know everything about a business error code.
Content
One row per value of ErrorCode: HTTP status, case, what the user sees (screen and message), entity in question, endpoints that return it.
Why this formalism
The problem type registry of RFC 9457, as a table.
Source
x-error-catalog and x-codes of openapi.yaml: the catalogue cannot diverge from the API contract.
