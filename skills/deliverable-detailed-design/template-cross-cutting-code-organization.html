Transactions and processes

The endpoint opens and closes the transactionThe handler of an endpoint that writes opens the transaction, calls the processes, then commits, or rolls back on the first rejection. A process PROC-xx always runs in the transaction of its caller: it never opens, commits or rolls back anything, it returns a result or a rejection. The sequences of the endpoints show it (x-sequence). Mechanism of the foundation: port, isolation level.
When a process existsA process PROC-xx exists when a piece of domain logic serves two callers or more (endpoints or processes), when it is a domain calculation or algorithm worth testing on its own, when it is a cascading effect (an action that triggers others on other objects), or when nothing calls it (scheduled task, consumption of a message). Otherwise, the logic stays in the endpoint, in its use case.

Frontend

Purpose
Know where each screen lives in the frontend code.
Content
One row per route: screen, components, state. Then the API access services and what is common to the screens.
Why this formalism
The front organization of the foundation applied to the product, as a table (C4 component view): one folder per top-level screen loaded on demand, one API access service per resource, the only one to inject HttpClient, state in signals (INV-30 to INV-40 of the foundation).
Reading
The endpoints each screen calls are in the per-screen view, not here.

  • API access services: one per resource; exchange types drawn from the schemas
  • Error translation: service that translates a code into a message MSG-xx, single catalogue of labels
  • Tolerant reading: the front ignores a response property it does not know, and translates an unknown enum value as the generic case of the screen, without crashing (INV-59). This is what lets a frozen operation grow through announced additions.

Open points

Purpose
List what remains to settle on the code organization.
Content
One point per row, sorted by decreasing impact: the subject, the hypothesis the code follows meanwhile, the question Q-xxx if it is asked to the PO.
Why this formalism
A table, because each point has the same attributes and compares with the others.
Reading
  • high the answer can change the data model, a frozen operation of the API contract or what structures the whole code
  • medium the answer can change a provisional operation, a process, a schema not frozen or a screen
  • low the answer only changes a label, a message, a value or an edge case
