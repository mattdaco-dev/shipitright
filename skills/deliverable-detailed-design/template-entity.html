Physical model

Purpose
Give the physical schema of the entity, precise enough to write the migration.
Content
The SQL DDL in the dialect of the store, each constraint commented with the rule it holds, then the rules the database cannot hold and the place where they live.
Why this formalism
The DDL is what the migration contains: the dev takes it over without translation.
Reading
An index carries in a comment the query it serves; a column of a later release carries its release, as an indication. The common conventions are in the persistence.

Open points

Purpose
List what remains to settle on this entity.
Content
One point per row, sorted by decreasing impact: the subject, the hypothesis the code follows meanwhile, the question Q-xxx if it is asked to the PO.
Why this formalism
A table, because each point has the same attributes and compares with the others.
Reading
  • high the answer can change the data model, a frozen operation of the API contract or what structures the whole code
  • medium the answer can change a provisional operation, a process, a schema not frozen or a screen
  • low the answer only changes a label, a message, a value or an edge case
