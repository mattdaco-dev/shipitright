Ce que fait le traitement et pourquoi c'est un traitement (deux appelants ou plus, calcul du domaine testé seul, effet en cascade, ou aucun appel : tâche planifiée, consommation d'un message).

Signature et transaction

À quoi sert
Donner le contrat du traitement dans le code.
Contenu
Sa signature dans le langage du socle (entrées typées, résultat, refus en valeurs de CodeErreur), puis la transaction où il s'exécute : toujours celle de son appelant (règle des transactions).
Pourquoi ce formalisme
Une signature typée est la forme la plus courte et la moins ambiguë ; le dev la recopie dans le domaine.
// module domain/agregat
nomDuTraitement(
  cmd: { entrée: type },                  // d'où vient chaque entrée
  deps: { depot: Repository; horloge: Horloge },
): Result<Sortie, 'CODE_ERREUR'>
Transaction
celle de l'appelant, endpoints en liens ; un traitement sans appelant (tâche, message) ouvre la sienne et le dit

Algorithme

À quoi sert
Dire ce que fait le traitement, dans l'ordre.
Contenu
Une étape par contrôle ou par action, chacune avec sa règle de gestion et son refus.
Pourquoi ce formalisme
Une liste numérotée fixe l'ordre (un contrôle avant l'écriture) sans prose.
  1. contrôle, sinon refus CODE_ERREUR en lien (RG-xx en lien)
  2. écriture par le dépôt : ce qui change

Cas limites

À quoi sert
Lister les cas que les tests du traitement couvrent.
Contenu
Une ligne par situation, avec son résultat attendu.
Pourquoi ce formalisme
Une table de décision : chaque ligne devient un test unitaire. Les tests imposés la citent sans la recopier.

Points ouverts

À quoi sert
Lister ce qui reste à trancher sur ce traitement.
Contenu
Un point par ligne, rangé par impact décroissant : le sujet, l'hypothèse que le code suit en attendant, la question Q-xxx si elle est posée au PO.
Pourquoi ce formalisme
Un tableau, parce que chaque point a les mêmes attributs et se compare aux autres.
Lire
  • fort la réponse peut changer le modèle de données, une opération figée du contrat d'API ou ce qui structure tout le code
  • moyen la réponse peut changer une opération provisoire, un traitement, un schéma non figé ou un écran
  • faible la réponse ne change qu'un libellé, un message, une valeur ou un cas limite
