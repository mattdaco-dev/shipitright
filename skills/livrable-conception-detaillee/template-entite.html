EN-xx : Nom de l'entité

Ce que l'entité représente en une ou deux phrases, et la règle la plus importante qu'elle porte.

Store store table nom_table Release MVP Version v0.1 Date JJ.MM.AAAA Auteur Architecte Statut brouillon

Modèle physique

À quoi sert
Donner le schéma physique de l'entité, assez précis pour écrire la migration.
Contenu
Le DDL SQL dans le dialecte du store, chaque contrainte commentée par la règle qu'elle tient, puis les règles que la base ne peut pas tenir et l'endroit où elles vivent.
Pourquoi ce formalisme
Le DDL est ce que contient la migration : le dev le reprend sans traduction.
Lire
Un index porte en commentaire la requête qu'il sert ; une colonne d'une release suivante porte sa release, à titre indicatif. Les conventions communes sont dans la persistance.
CREATE TABLE nom_table (
  id     INTEGER PRIMARY KEY,
  champ  TYPE NOT NULL CHECK (...),        -- RG-xx en lien, ce que la contrainte tient
  autre_id  INTEGER NOT NULL REFERENCES autre_table(id)   -- EN-xx en lien
);
-- la requête que l'index sert, avec l'endpoint ou le traitement en lien
CREATE INDEX nom_index ON nom_table(colonnes);

Règles hors de la base

  • RG-xx en lien : pourquoi elle ne peut pas être une contrainte (heure courante, autre ligne, session), et où elle vit (objet du domaine, TR-xx en lien) ; sans objet, retirer ce titre et la liste

Machine à états

À quoi sert
Montrer le cycle de vie de l'entité et ce qui la fait changer d'état.
Contenu
Une ligne par transition (de, vers, événement, garde, action), puis le diagramme d'états tiré de ce tableau. Sans cycle de vie, une phrase le dit.
Pourquoi ce formalisme
La notation UML événement [garde] / action, en deux vues d'une seule source : le tableau porte les liens et se relit ligne à ligne, le diagramme montre le cycle d'un coup d'œil.

Qui agit dessus

À quoi sert
Savoir qui crée, lit, met à jour ou supprime l'entité.
Contenu
Sa colonne de la matrice CRUD, endpoint par endpoint et traitement par traitement, puis les schémas qui en sont la projection.
Pourquoi ce formalisme
La matrice CRUD, standard de ce croisement ; la même que celle du sommaire, lue depuis l'entité.
Source
openapi.yaml et les pages des traitements : rien à écrire.

Points ouverts

À quoi sert
Lister ce qui reste à trancher sur cette entité.
Contenu
Un point par ligne, rangé par impact décroissant : le sujet, l'hypothèse que le code suit en attendant, la question Q-xxx si elle est posée au PO.
Pourquoi ce formalisme
Un tableau, parce que chaque point a les mêmes attributs et se compare aux autres.
Lire
  • fort la réponse peut changer le modèle de données, une opération figée du contrat d'API ou ce qui structure tout le code
  • moyen la réponse peut changer une opération provisoire, un traitement, un schéma non figé ou un écran
  • faible la réponse ne change qu'un libellé, un message, une valeur ou un cas limite
Source
Écrit ici une seule fois ; le générateur le reprend dans la vue des points ouverts.
