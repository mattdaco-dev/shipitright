# Create a project

## 1. Name

Ask the human for the project name if not given, and propose a short kebab-case slug
(`claim-declaration`). The project is created at the root of the current folder: check it is not
already a project (no `.team/` nor `docs/`). An existing `docs/` folder, even unrelated to
ShipItRight, makes the script refuse: tell the human, who moves it or picks another folder.

Also set the **project language**: the one the human writes to you in, unless they ask for another
(their end users may speak another language than they do: ask if in doubt). BCP 47 code: `fr`,
`en`, `de`, `pt-BR`… Full convention: `team/conventions/language.md` in the plugin.

## 2. Initialize

```sh
${CLAUDE_PLUGIN_ROOT}/team/scripts/init-project.sh --lang <code> <slug> "<Project name>"
```

The script creates:

```
<current folder>/
  .team/board/  forum/  questions/  journal.md  foundation.md (foundations to declare at framing)
        project.json ({ "language": "<code>" })
  docs/_assets/ (copy of ${CLAUDE_PLUGIN_ROOT}/team/assets, plus i18n.js: labels in the project language)  index.html (dashboard page, deliverable-dashboard template)
  docs/00-framing/ 10-analysis/ 20-specs/{epics,stories}/ 20-ux/ 30-design/api/ 40-qa/ 50-acceptance/ sprints/ adr/
  docs/10-analysis/index.html (analyses inventory) and docs/20-specs/backlog.html: generated by
    dashboard-pages.mjs, like the dashboard page
  prototype/  backend/  frontend/      (a .gitkeep in each empty folder)
  README.md  .gitignore
```

and a commit on the `design` branch (never a commit on `main`), holding only what the script created
or changed. The script checks everything before writing, and removes what it wrote if it fails:

- the name goes through as is, special characters included (`R&D / Loans`); the slug is kebab-case;
- an existing `README.md` is not overwritten: the script appends a `## ShipItRight` section to it;
- a folder that is not a git repository: `git init`; an existing repository: the project must be at
  its root, an existing `design` branch is reused if it does not already hold `.team/` nor `docs/`
  and the working tree has no pending change, otherwise the script refuses;
- `.team/` or `docs/` already present: the script refuses, without writing anything.

## 3. Language without provided labels

The plugin provides `fr` and `en` labels (`${CLAUDE_PLUGIN_ROOT}/team/i18n/<language>/`). For another
language, generated pages show in English until the project has its labels:

1. read each file `${CLAUDE_PLUGIN_ROOT}/team/i18n/en/*.json` and translate it into the project
   language, keys and `{…}` parameters unchanged, CLDR plural forms of the language (`one`, `few`,
   `many`, `other`…); for `gherkin`, the official Gherkin keywords in that language;
2. write it all to `.team/labels.json`: `{ "<namespace>": { "<key>": "…" } }`, one object per file
   (the file name without `.json` is the namespace);
3. also translate the header of `.team/journal.md`, `.team/foundation.md` and the ShipItRight section
   of `README.md`, written in English by the script;
4. regenerate: `node ${CLAUDE_PLUGIN_ROOT}/team/scripts/dashboard-pages.mjs .` (it also rewrites
   `docs/_assets/i18n.js`), then commit on `design`.

## 4. Notion board, if the Notion MCP is available

Without the Notion MCP, skip this step: no board, no `.team/notion.md`, the local board is enough.
Otherwise, follow the `shipitright:notion-board` skill, section 1: **ask the human where to create
the board** (URL of a parent page, or agreement for a private page), then create the database, the
views, and `.team/notion.md`. The Notion button of the dashboard page reads this file: regenerate the
page (next section).

## 5. Start framing

Go on with the framing interview (skill `shipitright:deliverable-framing`), once the project is
created, not before. Foundations (stack, design system) are declared during the interview: the PO
asks the human for theirs, or decides with them that they will be created in the project. The
tooling the stack foundation requires is checked only before the first sprint, by the Architect.

## Keep the dashboard page up to date

The dashboard page (`docs/index.html`, which replaces the portal), the backlog page
(`docs/20-specs/backlog.html`) and the analyses inventory (`docs/10-analysis/index.html`) are not
edited by hand: they are generated from the project files (journal, board, questions, `status` and
`verdict` meta of deliverables, analysis pages, stories, story map, roadmap, sprint pages, campaigns,
acceptance reports). The PO regenerates them:

- at each wave sync;
- at each gate, once the decision is logged in the journal and the deliverable status updated;
- at each merge into `sprint/N`.

```sh
node ${CLAUDE_PLUGIN_ROOT}/team/scripts/dashboard-pages.mjs .
```

No journal line is added for these pages: they read the events already logged, with no planned date
nor delay (dates are in the roadmap calendar). `check-deliverable.mjs` runs
`dashboard-pages.mjs --check` and flags a page that is out of date. Format and rules: skill
`shipitright:deliverable-dashboard`.

Assets of an existing project are updated with `cp ${CLAUDE_PLUGIN_ROOT}/team/assets/* docs/_assets/`
when `doc.css` or `doc.js` change.
